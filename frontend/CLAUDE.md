# CLAUDE.md — Frontend (React + shadcn/ui)

Scope: everything under `frontend/`. Root `CLAUDE.md` also applies. The UI is the demo — it is judged on product thinking, UX and whether it visibly works.

## Stack
- Vite + React 19 + TypeScript (`strict: true`, `noUncheckedIndexedAccess: true`). Lint: oxlint (`src/components/ui/**` ignored).
- Package manager: **pnpm**.
- Styling: Tailwind CSS + **shadcn/ui** (add components with `pnpm dlx shadcn@latest add <name>`; never hand-copy them). Icons: lucide-react.
- Routing: react-router. Server state: TanStack Query. Local UI state: React state/context; add zustand only for cross-panel selection state if context gets messy.
- Map: own SVG (no tiles, no map library): local meters around the base, pan/zoom via `useMapViewport`. Works offline on stage. Charts: shadcn `chart` (Recharts).
- API types: generated by `openapi-typescript` into `src/api/schema.d.ts` (`make gen-types` from the root). Never hand-write API types; add UI aliases in `src/api/types.ts`.

## Component rules
- Function components + hooks only. One component per file, named export, file name = component name.
- Components ≤ ~150 lines; extract subcomponents instead of growing.
- Presentational components take typed props and never fetch. Pages and hooks fetch.
- No business logic in the UI: risk levels, distances, verdicts come from the API. The frontend only formats and visualizes.
- All user-facing text comes from `i18n/tr.ts` (default language Turkish for the jury). Code and identifiers stay English.
- Every async view has explicit loading (skeleton), empty and error states. Never a blank panel, never a raw error object.
- Accessibility basics: buttons are `<Button>`, icons have `aria-label`, color is never the only signal (risk badge = color + text).

## Visual language (ops center, day mode)
- Day mode by default (user decision, 26 Sep): shadcn CSS variables in `index.css` `:root` — soft blue-gray page, off-white cards (deliberately below pure white to cut glare), map surface `bg-map` (`--map`), 1px borders, rounded-lg. The dark palette stays in `.dark` (add `class="dark"` to `<html>` to use it). Pick text/stroke shades that read on white (`-600`/`-700`); overlays on drone photos keep dark labels.
- Fonts: Inter for UI, JetBrains Mono for coordinates, IDs, times and numbers.
- Risk colors (single source: `lib/risk.ts`): LOW = emerald, MEDIUM = amber/mustard, HIGH = orange, CRITICAL = red (with subtle pulse). Report verdicts: CORROBORATED = emerald, CONTRADICTED = red, UNVERIFIED = zinc, IRRELEVANT = muted/hidden.
- Accent: teal-cyan (`primary`) for selection/hover, links and the agent's "active step".
- Density: information-rich but calm. Prefer small caps labels + large numbers for KPIs. No gradients except the active step glow.
- Motion: subtle only (fade/slide 150–250 ms). Timeline steps animate in as SSE events arrive; the brief card reveals last.

## Analysis page layout (demo centerpiece)
Modeled on the organizer's "Uçtan Uca Örnek" (case brief slides 16-25): a step player.
- Header: frame picker, zone, capture time, RiskBadge (after the last step), `PlaybackControls` (◀ Oynat/Duraklat ▶ Baştan; arrow keys + space via `usePlayback`).
- Left ≈55%: `SceneStage` + `StepScene`, which changes per step: corners (1), boxes (2), schematic placement + to-scale zone inset (3), track dots at capture time (4), to-scale route with stops (5), report cards with checks (6), rubric bars (7), evaluation card (8).
- Right: `AgentTimeline` — operator request bubble, then one `StepCard` per revealed step ("3/8 · ARACI TESPİT ET", Turkish sentence + mono facts from `lib/narrative.ts`, raw toggle for mentors). Clicking a card jumps to that step.
- Bottom after the last step: `BriefCard` + `VehicleTable`. Evidence chips are clickable.
- Live SSE (P3) will drive the same player: each `step_completed` event advances it.
- **Linked selection:** selecting a vehicle (box, table row, evidence chip or map track) highlights it everywhere. Implement via a single `selectedEvidenceId` context.

## Auth (mock, demo only)
- Every route except `/login` sits under `RequireAuth`; `/admin` also requires `role="admin"`. Roles: `admin` sees everything plus `/admin`, `user` sees every other page.
- Mock accounts live in `lib/auth.ts` (`admin / admin123`, `operator / operator123`) and ship in the bundle; nothing is protected. To use a backend, replace only the body of `login()`.
- Session is `localStorage['akya.auth.session']`; unreadable or invalid = logged out. Logout is a full load of `/login`.

## SSE
- `useAnalysisStream(analysisId)` uses `EventSource`, parses events per AGENT_DESIGN §5 into a reducer (`steps`, `brief`, `status`, `warnings`), closes on `done`/`error`, reconnects once.
- Replay uses the same hook with `?replay=true` — the UI must not know the difference.

## Demo robustness
- `VITE_USE_MOCKS=true` serves `src/mocks/` so the UI can be built before the backend exists and shown if the backend dies.
- A status indicator in the top bar shows API and LLM health from `/api/health`.
- Test at 1920×1080 and 1366×768 (projector). No horizontal scroll; panels scroll internally.

## Watch demo (`/watch`)
- Replays a recorded multi-agent watch run from `GET /api/watch/recordings/{id}` (no LLM calls on stage). Recordings are JSONL event logs in `backend/recordings/`, made with `make watch-demo SAVE=<name>`.
- Plays on the same simulated clock and `TimeBar` as the field map (default 15×); the clock sits upper left on both maps. Zone names, image names, the base title and (on the watch map) the legend are not drawn on maps; vehicle tracks are straight polylines through the samples (smoothed curves were tried and reverted); a frame shows a short "Görüntü alındı · HH:MM" popup for 3 simulated minutes after capture. The field map draws only the last 20 min of each track (full route for the selected one). Each tick's outputs "stream" during the 5 simulated minutes before the tick (`SCHEDULE` in `lib/watchDemo.ts`): watchers type in parallel, then the supervisor, then its alert; a vehicle's color changes when the watcher that judged it finishes. To keep the map readable, vehicles are dots colored by level, or a level-colored disc with a lucide type icon (car, van, truck, bus) once a frame detection confirmed the type (`VehicleTypeIcon`, `vehicleTypes` in `lib/watchDemo.ts`); HIGH vehicles show their whole route so far while they stay HIGH (drawn in when they become HIGH, `VehicleState.highSince`), vehicles in the latest operator alert their last 45 min (`alertFocus`) and only the selected vehicle shows its id and full route. Pausing or scrubbing replays the same state.
- LLM text is shown short (`concise`, first sentence) with "devamı" to open the full text; every vehicle id (`T0xxx`) in any LLM text is a link (`AgentText` / `LinkedIds`, `useVehicleLink`).
- `lib/watchDemo.ts` only indexes and schedules events; levels, reasons and alerts are exactly what the agents wrote.
- Side panel has two tabs. **Baş Denetçi** is the operator view of a real-time caution system: threat level, one-line situation, the alert (urgency, headline, short description, vehicles) and the alert log; nothing else (patterns, level changes and traces are analyst detail). **Gözcüler** holds the watcher cards with their traces.
- Deep links for the demo script: `/watch?recording=<id>&tick=<1-based>&at=<HH:MM>&vehicle=<track_id>&tab=watchers`.
